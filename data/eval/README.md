# 评测集说明（data/eval/）

## 这是什么

`qa.jsonl` 是**检索质量**评测集：**18 道题**，覆盖情绪自助手册的全部 6 章。
每题都标注了**应该命中的条目**（`expect_ids`）以及该条目在手册里的行区间（`expect_lines`）。

> **变更说明（重要）**：这里原先是一份 40 题的 IT 运维手册评测集。
> 那套语料（`data/knowledge_base.txt`）与评测集已按需求**整体删除**，
> 项目现在只有一个知识库 —— **情绪自助手册**（`data/emotional_handbook.txt`）。
> 题目重出后**只有 18 题**：样本小是实话，结论不要外推得太远。

## 为什么要刻意"口语化"改写

题目**不是**照抄条目标题，而是改写成真人会说的话：

| 条目标题（手册原文） | 评测题（改写后） |
|---|---|
| 【E1-04】先解决"没睡好"这件事 | 躺下就是睡不着，脑子停不下来 |
| 【E3-02】拖延：把任务切到"小得可笑" | 事情堆着不想动，一想到就烦躁 |
| 【E1-01】4-7-8 呼吸：给绷紧的身体一个刹车 | 一焦虑就胸口发紧、脑子停不下来怎么办 |

如果题目直接用标题原词，关键词检索会"抄答案"式拿高分，评测就失去意义。
**现在的题目对纯关键词检索是不利的** —— 这正是想量化的东西：
在"用户不会用官方说法提问"的情况下，检索能不能把正确条目捞上来。

## 格式

每行一条 JSON：

```json
{
  "id": "e04",
  "chapter": 1,
  "question": "躺下就是睡不着，脑子停不下来",
  "expect_ids": ["E1-04", "E3-01"],
  "expect_lines": [[58, 66], [106, 112]]
}
```

- `expect_ids`：期望命中的条目编号（判定时看片段正文里有没有 `【Ex-xx】`）
- `expect_lines`：该条目在 `data/emotional_handbook.txt` 中的行号区间
- 两个条件**满足其一**就算命中，避免"片段从条目中间开始、正文里没带编号"的误判

## 怎么跑

```bash
python scripts/eval_rag.py                 # 全量 18 题，打印每题名次与汇总指标
python scripts/eval_rag.py --limit 5       # 抽样快跑
python scripts/eval_rag.py --k 5           # 改变 top-k
python scripts/eval_rag.py --json out.json # 另存明细（含每题实际召回的条目 id）
```

指标口径（写死在脚本里，避免口径漂移）：

| 指标 | 含义 |
|---|---|
| `hit@1` | 第一名的片段就是期望条目 |
| `hit@3` | 前 3 个片段里有期望条目（**这是实际交给模型的量**） |
| `hit@5` | 前 5 个片段里有期望条目 |
| `MRR` | 第一个命中位置的倒数均值（1.0 = 每次都在第一位） |

**未命中不计入命中率，但计入总数** —— 这是最容易做假的地方。

## 最近一次实测（2026-10，18 题，关键词检索）

```
hit@1 = 0.778   hit@3 = 0.944   hit@5 = 1.000   MRR = 0.863   未命中 0 / 18
```

有 4 题回答正确但排在 2~3 位（`E2-01` / `E2-04` / `E4-01` / `E5-01` / `E6-01`）。
Agent 实际把 top-3 交给模型，所以 `hit@3` 才是功能上的关键数字。

## 维护约定

- **改了手册就要同步行号**：不过 `scripts/eval_rag.py` 会**自己按文件算行区间**
  （上一版靠手写行号，手册一改就失效）；`qa.jsonl` 里的 `expect_lines` 仅作交叉校验。
- 新增题目保持"口语化"风格，**不要把条目标题原词写进问题**。
- 发现 MISS 时**先判断是不是口语/书面用词不匹配**（多半是），
  该补的是 `src/chat/knowledge.py` 里的同义词表，而不是把题目改得更容易命中。
