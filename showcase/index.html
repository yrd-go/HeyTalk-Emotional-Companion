02 / What it does

四件事，比“会聊天”更重要。

所有能力都围绕同一个问题：如何让生成式系统在真实对话里可解释、可恢复、可停止。

01

安全先于生成

高危场景走固定分流与真实求助渠道，零模型调用；中危回答必须带求助出口。

Deterministic gate
02

等待过程可见

思考状态、耗时与流式输出持续可见；完成之后，思考记录也不会凭空消失。

Transparent latency
03

记忆必须确认

抽取结果只是候选，不自动写进档案。一条错误记忆会影响以后每一次对话。

User-owned memory
04

工具失败不穿透

天气、翻译与联网搜索都有降级路径；网络或上游失败不会把代码异常丢给用户。

Graceful degradation

03 / Architecture

确定性规则在前，生成模型在后。

把最容易出错的部分移出模型自由生成，再让前端只消费可恢复的事件流。

Negative result matters.

回应规划层与当前版本的盲评是 50% 对 50%，但平均耗时从 10.5 秒升到 16.6 秒。因此没有把它作为卖点，而是把它当作一次被数据否决的尝试。

05 / Boundaries

知道哪里不能吹，
才知道项目做到哪。

01

不是心理咨询或医疗产品

安全分流与求助渠道能降低风险，但不能替代专业帮助。

02

没有真实留存证据

盲评衡量的是评委偏好，不是“用户会不会回来”。

03

不是常驻在线服务

GitHub Pages 只承载静态作品集；交互演示由作者在本机现场运行。

04

功能开发已冻结

没有新的评测信号时，继续堆字和堆功能只会扩大故障面。

A portfolio prototype, not a promise.

我在这个项目里练习的，
是把“能做”变成“知道该做到哪里”。
